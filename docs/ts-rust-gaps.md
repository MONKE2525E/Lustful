### Feature counts

`prod uses` in this report sums the primary raw keys of a feature over the prod and gen buckets. Recomputing the same sum from the inventory `raw-counts.json` gives differences of 0 to 1.4 percent for every large feature. Examples: closures 6,888 against 6,811 recomputed (raw `closure` alone is 6,463 prod in both), user macros 3,179 against 3,179, Rc and RefCell types 4,505 against 4,505, iterator chains 3,596 against 3,547, `dyn Trait` 1,960 against 1,959, threads 1,130 against 1,130. The two larger ratios are on small counts and come from the tool files above: named lifetimes +3.9 percent (54 uses) and the wider std runtime +4.0 percent (12 uses). One new count has no inventory counterpart: serde derives in the codegen tools (15 uses) land in `derives.unknown`.

Findings (112,665) are not the same unit as inventory uses. A finding is one primary-key hit in any category, deduped by (feature, file, byte range). One syntax site can make several findings under different features, for example `Box<dyn Fn>` counts under both `core.result_try` and `dyn.trait`.

The gap stays under 0.7 points of lines at every step, and file counts differ by at most 2. The small remaining gap comes from three rule changes, not from missed code:

1. The inventory script treated every unmatched raw key as supported today. This scanner adds catch-all rules (`std.other`, `ext.unknown_crate`, `derives.unknown`, `unsupported.other`), so a file blocks until its last unknown path gets a rule or a milestone. That is why the last step stops at 774 of 778 files instead of all of them: the codegen tools use serde, which has no adapter decision yet.
2. Const generic parameters have no compiler milestone here (milestone 8 closes them by rewrite), where the inventory step 0 counted them as a codemod.
3. `std.use.*` keys are classified by their type form, so a file that only writes `use std::sync::Arc;` blocks on threads. The inventory rules only matched type and expression forms for some of these paths.
