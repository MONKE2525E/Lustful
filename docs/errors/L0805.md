# L0805: local ambiguity in a macro call

The call could be read two ways: one input token fits two different
places in the matcher, as when a repetition of a fragment is followed
by another fragment that also accepts it. Rust stops here; guessing
could pick the wrong program.

## Wrong

```rust
macro_rules! m {
    ($($i:ident)* $j:ident) => {
        ()
    };
}

fn main() {
    m!(x);
}
```

## Fixed

```rust
macro_rules! m {
    ($($i:ident),* ; $j:ident) => {
        ()
    };
}

fn main() {
    m!(; x);
}
```
