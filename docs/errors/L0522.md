# L0522: this attribute is not supported yet

<!-- rustc-wrong: pass -->

Lust knows this attribute by name (`target_feature`, `link_section`, and kin)
but does not act on it yet, so it rejects it instead of ignoring it.
An attribute name lust does not know at all gives L0402 instead.
Remove the attribute. Rust accepts the wrong example; lust does not.
`#![recursion_limit]` is honored from 128 up; a lower value is
rejected, because rustc also checks type, trait, and layout depth
against it, and lust does not track those.
`#[no_implicit_prelude]` is rejected too: lust would still find prelude
types, variants, trait methods, and std macros in such a module.
`cfg` on items and `repr` are the exceptions: expansion evaluates
item `cfg` for the host target (see ARCH 6.1), and layout uses
`repr` (see ARCH 4.4). The advisory attributes `inline`, `cold`,
`must_use`, and `deprecated` are accepted and ignored (ARCH 1.6), and
`track_caller` is handled (check/caller.rs). `non_exhaustive` is
handled too: it changes what other crates may construct and match.
`global_allocator` is handled for known allocator types (std
`System`, the `tikv-jemallocator` adapter's `Jemalloc`): the
static is accepted and the lust runtime keeps its allocator.

## Wrong

```rust
#[target_feature(enable = "avx2")]
fn f() {}

fn main() {
    println!("hi");
}
```

## Fixed

```rust
fn main() {
    println!("hi");
}
```
