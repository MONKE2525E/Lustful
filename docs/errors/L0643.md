# L0643: a std item of this name may win over the trait item here

A method call or a `Type::item` path names an item that a trait from
outside std declares, and std has an item of the same name for the
receiver type. rustc picks std's inherent item when it comes first in
its probe order (or at the same probe), and a std trait's item next to
the user trait's item is ambiguous. lust does not model every std item,
so it gives this code instead of calling the trait item where rustc
would not. The table of std items comes from the std docs
(`scripts/gen-std-inherent.py`). rustc rejects the wrong example too:
it picks String's inherent `as_mut_vec`, which is an unsafe fn (E0133).
Name the trait in the call when you mean the trait item.

## Wrong

```rust
trait Shout {
    fn as_mut_vec(&mut self) -> usize;
}
impl Shout for String {
    fn as_mut_vec(&mut self) -> usize {
        0
    }
}
fn main() {
    let mut s = String::from("hi");
    println!("{:?}", s.as_mut_vec());
}
```

## Fixed

```rust
trait Shout {
    fn as_mut_vec(&mut self) -> usize;
}
impl Shout for String {
    fn as_mut_vec(&mut self) -> usize {
        0
    }
}
fn main() {
    let mut s = String::from("hi");
    println!("{}", Shout::as_mut_vec(&mut s));
}
```
