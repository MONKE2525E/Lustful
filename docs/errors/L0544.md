# L0544: non-binding let on a synchronization lock

`let _ = m.lock();` binds nothing, so the guard drops at once and the
lock is released before the next statement. rustc denies this by
default (lint `let_underscore_lock`) for a `MutexGuard`,
`RwLockReadGuard`, or `RwLockWriteGuard`, alone or as the `Ok` type of
a `Result`, at any `_` in a `let` pattern and in `_ = ..`. An
`#[allow]`, `#[warn]`, or `#[expect]` of the lint (or of the
`let_underscore` group) on the statement or the fn lifts it.

## Wrong

```rust
use std::sync::Mutex;

fn main() {
    let m = Mutex::new(1);
    let _ = m.lock();
    println!("done");
}
```

## Fixed

```rust
use std::sync::Mutex;

fn main() {
    let m = Mutex::new(1);
    let _guard = m.lock();
    println!("done");
}
```
