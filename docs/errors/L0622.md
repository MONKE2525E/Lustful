# L0622: `Self::V` is both a variant and an associated type

Inside a trait impl for an enum, the type path `Self::V` names the
associated type `V` of the trait. When the enum also has a variant
named `V`, rustc denies the path by default (lint
`ambiguous_associated_items`, in the `future_incompatible` group),
because a later Rust may resolve it to the variant. An `#[allow]`,
`#[warn]`, or `#[expect]` of the lint or its group lifts it. lust reads
these levels on the method, the impl, enclosing modules, and the crate.
The value path `Self::V` (the variant) is fine.

## Wrong

```rust
enum E {
    V,
}

trait Tr {
    type V;
    fn f() -> Self::V;
}

impl Tr for E {
    type V = u8;
    fn f() -> Self::V {
        1
    }
}

fn main() {
    let _ = E::V;
    println!("{}", E::f());
}
```

## Fixed

```rust
enum E {
    V,
}

trait Tr {
    type V;
    fn f() -> Self::V;
}

impl Tr for E {
    type V = u8;
    fn f() -> <Self as Tr>::V {
        1
    }
}

fn main() {
    let _ = E::V;
    println!("{}", E::f());
}
```
