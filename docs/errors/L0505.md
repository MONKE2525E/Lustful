# L0505: this module path form is not supported yet

Modules, imports, same-crate module paths, and paths into dependency
crates lust compiles from source (workspace and path dependencies)
work. What remains under this code: path forms the checker cannot
place, such as a path through a name that is not a module, a type, or
a dependency crate of this crate. A dependency with no lust source,
adapter, or shim form reports L0508 instead. Two more forms report
here, because lust does not know every name a std module exports: a
glob import of `std::io`, `std::fmt`, or `std::thread` (each has its
own `Result`); a name from a user glob in a module that also has a std
glob (it may be ambiguous); and, inside a block with a std module glob,
a name lust would find outside that block, or an uppercase binding.
Import the std items by name instead. `super::f` or `crate::f` to a
crate-root item is L0505 too when a nearer item, import, or local of
the same name is in scope.

## Wrong

```rust
fn main() {
    other::thing::go();
}
```

## Fixed

```rust
fn go() {
    println!("go");
}

fn main() {
    go();
}
```
