# L0705: lust cannot prove this dyn lifetime bound

<!-- rustc-wrong: pass -->

A `'static` object bound (`dyn Trait + 'static`, or the default
under `&'static dyn Trait`) needs the concrete type to live for
`'static`. lust erases lifetimes inside types, so it cannot check
that for a type that holds references (or a type parameter), and
it rejects the coercion instead of guessing. Rust accepts the wrong
example, because the reference there is `'static`. Use a concrete
type without references, or drop the `'static` bound.

The same holds for uses that need a `dyn` value to be `'static`:
a method of `impl dyn Trait` or of `impl Other for dyn Trait` (an
impl header's `dyn Trait` means `dyn Trait + 'static`), a coercion
to `dyn Trait + 'static`, and a call through `dyn` to a method with
`where Self: 'static`. lust accepts these only in a body where no
`dyn` value can come from a shorter lifetime: no `&dyn Trait`
parameter, no call that returns `&dyn Trait`, and no `dyn` value
made from a type that holds a borrow. Rust infers each lifetime
separately, so it accepts some bodies lust rejects. Write
`impl dyn Trait + '_` for an impl that takes any lifetime. A trait
bounded by `'static` (`trait Trait: 'static`) makes every
`dyn Trait` `'static`, as in Rust, so its uses need no proof.

## Wrong

```rust
trait Tr {
    fn get(&self) -> u8;
}

impl Tr for &u8 {
    fn get(&self) -> u8 {
        **self
    }
}

static X: u8 = 5;

fn keep(d: &(dyn Tr + 'static)) -> u8 {
    d.get()
}

fn main() {
    let r: &'static u8 = &X;
    println!("{}", keep(&r));
}
```

## Fixed

```rust
trait Tr {
    fn get(&self) -> u8;
}

impl Tr for u8 {
    fn get(&self) -> u8 {
        *self
    }
}

static X: u8 = 5;

fn keep(d: &(dyn Tr + 'static)) -> u8 {
    d.get()
}

fn main() {
    println!("{}", keep(&X));
}
```
